Mahler's 3/2 problem · a computation, on one laptop

No Mahler Z‑number below 2⁶³

In 1968 Kurt Mahler asked whether some positive number ξ keeps the fractional part of ξ, ξ·3/2, ξ·(3/2)², ξ·(3/2)³, … below one half, for ever. Such a number is called a Z-number. Nobody knows whether one exists, and Mahler guessed that none does. We checked every positive number below 263, about 9.2 quintillion. None of them passes. In 2009 Dubickas and Mossinghoff showed by computer that a Z-number, if there is one, must exceed 257. The census on this page moves that floor 64 times higher, and it took a quarter of an hour on a laptop.

Seen

Stated

The result (computed, exact)

For every integer n with 1 ≤ n < 263, no real ξ in [n, n+1) has the fractional part of ξ·(3/2)j below ½ for every j ≥ 0. Call the horizon of n the first j at which no ξ in [n, n+1) is left below one half: every start below 263 has a finite horizon, at most 157. A number in (0, 1) fails too: its multiples ξ·(3/2)j grow by half each step, so one of them lands between ½ and 1. So there is no Z-number in (0, 263).

Why there is one candidate per integer (Mahler 1968; proved)

Write ξ·(3/2)j = nj + uj, with nj an integer and uj in [0, ½). Then the integer parts follow one fixed map, nj+1 = ⌈3nj/2⌉. The fractional part is fixed by the future parities bk = nk mod 2 alone:

uj = Σk≥0 bj+k · 2k / 3k+1

So the integer part n0 decides everything. Each unit interval [n, n+1) holds at most one Z-number, and the question becomes whether the orbit of some positive integer under ⌈3x/2⌉ keeps every one of those sums below ½.

How 9.2 quintillion candidates are checked in minutes

The first T parities of an orbit depend only on n mod 2T, its lowest T binary digits. So every start that shares those digits shares its early life. The census walks the tree of low digits. Along each branch it keeps the exact interval of fractional parts still alive, as integers over a power of two. When an interval empties, every start below that branch dies at once, sometimes trillions together. A start that survives all 63 digits runs on alone until it fails. The 4,499 starts still alive after 124 steps were replayed in exact rational arithmetic; the longest horizon was 157. The total is checked: exactly 263 − 1 starts, each with a finite horizon.

How it was checked

Before the full run, the census matched an independent exact-fraction computation on every start below 220. The full run was repeated, with the same 4,499 stragglers and the same record. Our reviewing model, GPT, audited the source and recomputed fixed cases independently. Dubickas and Mossinghoff's 2009 table lists one of our record starts, 9850069454682037, which fails at step 137, so the two searches use the same definitions. One more cross-check came out of the counts: the number of surviving digit patterns of each length equals, exactly, the word count of the base-3/2 digit system (the greedy beta-shift), at every length below 63.

The other half

Mahler's question is usually asked for positive ξ. For a negative ξ the same question is equivalent to asking for a positive η whose fractional parts all stay in the upper half (½, 1), because the map n ↦ −1 − n turns one problem into the other: it commutes with ⌈3x/2⌉ and swaps every parity. Akiyama, Frougny and Sakarovitch state the question for every nonzero ξ, and we found no published treatment of this half on its own.

The negative starts (computed, exact)

The same census run on every negative integer part x with −263 < x ≤ −1: every one has a finite horizon, the longest 153, at x = −6964446546082240544. So no positive η up to 263 − 1 keeps every fractional part of η·(3/2)n in (½, 1). As the symmetry requires, the counts over the first 63 steps match the positive side exactly. The records and the tail follow the same chance law: 4,622 starts alive at step 124, against 4,499 on the positive side.

Checked, here, now

Type any positive integer n, or press one of the record starts. Your browser follows its orbit under ⌈3x/2⌉ with exact integer arithmetic and reports the step at which no ξ in [n, n+1) is left below one half.

The start 4 is the small case worth watching: some ξ in [4, 4½) keeps below one half for j = 0 to 11, a horizon of 12. Starts 1, 2, 3 and 5 have horizons 4, 3, 2 and 6.

Compute is the only limit

This ran on a single Apple M5 MacBook Pro, in about a quarter of an hour (798 seconds on 9 cores). The work grows by about half again for each extra binary digit: 260 took 237 seconds and 263 took 798, a ratio of 3.37 against (3/2)³ = 3.375. Extrapolating:

The walk splits by the lowest digits into independent pieces, so it spreads over any number of machines with no communication. Going beyond 263 needs wider integers: start values past 64 bits, and past about 280 wider intermediate values in the walker too. What it is and what it is not

It is an exact finite verification, and it extends a published bound by a factor of 64. It is also good evidence of a mild kind: the record survivors grow like chance, about 2.4 steps per binary digit, and nothing below 263 behaves strangely. It is not a proof. Any finite range can be checked, but "for ever" cannot be reached this way: Turing's 1936 point, that finitely many checks never settle a question about all numbers without an essentially new argument. A Z-number could still exist far above any bound a computer will ever reach. We are not calling 263 the current record either: a brief search found no improvement on 257 since 2009, but we have not combed the later literature. The census is one party's computation, audited at the source by a second, not yet replayed in full by anyone else.
